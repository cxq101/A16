# 碎光收藏室：固定桌面美术样板

> 历史样板（2026-11-24 归档提示）：用户随后认为当前美术效果不足，本文内容与工期不作为商业美术验收或预算。现行方向见 [美术方向](../docs/art-direction.md)，最新待审阅状态见 [资产登记](../.project/artifacts.json)，字段以 [卡牌规范](../docs/card-spec.md) 为准。

## 已确认的方向

用户已通过上一轮试玩确认：三维表现提升了体验，倾斜视角没有影响辨认和归位。因此本轮沿用固定倾斜镜头、二维卡图、真实三维桌面；仍保持两张卡、十二片、相同归位规则，没有扩大内容数量。

最新版双击 `desk3d.html`。顶部“上一版对照”打开 `desk3d-study.html`，是上一轮独立文件的快照；原二维版本仍为 `demo.html`。新样板采用 `fragment-desk3d-art-v1` 独立存档，保留前两版的进度。

## 本轮实际交付

| 层次 | 内容 | 复用方式 |

| 第二张 | 《赤砂之塔》沿用版式，替换为沙丘、日轮和灯塔 | 验证共用模板及冷暖配色 |

可编辑卡面原稿在 `dist/desk3d/assets/moon-whale.svg` 与 `sand-tower.svg`。`art-assets.cjs` 是生成入口，修改原稿后再次构建会被它覆盖，应在该脚本中修改或明确调整生成流程。

本轮全部使用代码、SVG 与程序纹理。没有付费素材、外包采购或 AI 位图；新增资产采购支出为零。这不等于人工制作成本为零。

## 可采用的视觉规格

- 整体：安静的星图收藏室。主色为胡桃木、墨绿、黄铜，卡面保留冷暖主题差异。
- 卡面比例 2:3，矢量母版 720×1080 坐标；运行时生成 720×1080 纹理，每片 360×360。正式版若增加近距离观赏，可以提高导出分辨率，母版不需重画。
- 每片应有可辨认的主体、色块或线条。不能只看完整卡好不好看，还要检查六片是否出现大片近似空白。
- 背纹、边框与文字位置统一。金属效果只作用于印边遮罩，主体仍表现为印刷图案；关闭光泽时同时关闭金属效果。
- 纹理优先服务主次：卡片最清晰，桌垫次之，道具帮助营造尺度。当前桌面纹理仍略密，若干扰视线，应降低对比，而不是增加细节。
- 正式交付应附带字体许可、色板、源文件与导出图。本样板中文字使用系统字体，跨设备字形可能不同，尚未完成字体定版。

当前桌面由七组道具构成：桌面、灯、桌垫/托盘、收藏册、笔、纸卡堆、放大镜。都是程序造型，还没有美术软件中的专用 UV、完整 PBR 贴图包、LOD 或正式引擎资产，因此不能把它们视为已经完成外包交付的模型包。

## 操作反馈的当前节奏

| 动作 | 当前时长 | 目的 |
| --- | ---: | --- |
| 拿起 | 约 0.11 秒 | 快速响应，抬起但不挡住相邻图案 |
| 正确归位 | 约 0.18 秒 | 吸附清楚，连续操作顺畅 |
| 完成等待＋抬起展示 | 约 0.24＋0.48 秒 | 先确认最后一片落好，再展示完整卡 |
| 翻面 | 约 0.5 秒 | 正背面可辨认 |
| 入册 | 约 0.58 秒 | 比上一轮 0.75 秒更短，保留去向反馈 |

动画会替换同对象上相互冲突的补间，减少快速点击时的状态抢占。归位仍只校验卡片与位置，不增加旋转谜题、手部操作或物理堆叠。

## 成本：这一轮能确认什么

资产数量和复用关系已经明确：同规格新卡需要新插画与数据，不需要新的碎片模型、射线拾取、归位动画、入册动画或一套新桌面。独立插画将是内容扩充时的主要持续投入。

但本轮由工具辅助完成，没有进行美术人员完整制作流程的计时，因此不能把对话耗时当成人工工时。上一轮“一套固定桌面在正式引擎完成约 8–14 人日”的估计仍属于预算假设，不是已经核实的实际成本。当前尚不足以负责任地把这个区间进一步压缩。

以熟悉工具的开发者/美术、每人日八小时、保持当前矢量插画复杂度为假设，可分开预留：

| 项目 | 预算假设 | 是否按卡片数量增长 |
| --- | ---: | --- |
| 正式引擎中的共享桌面、交互、精修与验证 | 8–14 人日 | 同一桌面基本不增长；仍需内容检查 |
| 共用卡框、背纹、印边遮罩与导出模板 | 0.5–1 人日 | 一次投入 |
| 第一张主视觉插画 | 1–2.5 人日 | 独立题材需要新画 |
| 在已定风格内制作第二张 | 0.5–1.5 人日 | 按构图与内容复杂度变化 |
| **共享桌面＋两张代表卡** | **约 10–19 人日** | **另留返工空间** |

这不是本轮已经发生的人力支出，也不是外包市场报价。它不含整款游戏、成长系统、Steam 接入、宣传美术和整体测试，预算仍建议留约 20%–30% 返工空间。若改成精细厚涂、角色卡或高复杂度特效，这组插画估计应重新评估。

要得到可信的单卡成本，下一步应选 1–3 张不同构图的卡，按“构图草稿→定稿→模板适配→六片辨认检查→引擎效果检查→修改”计时，并记录每一步返工。确认每张耗时后，再乘以计划内容量；目前不宜承诺几十张卡的总价。

## 检查记录

- 两张卡全部拼完、真实拖放与点击归位、错误卡片拒绝、翻面、两次入册、收藏展示、刷新恢复均通过浏览器检查，无页面脚本异常。
- 图鉴两张 SVG 的渐变定义使用独立标识，已修正同页展示时第二张误用第一张背景渐变的问题。
- 1440×1000 与 1280×720 布局已查看，720p 下主操作按钮可见；390px 无横向溢出。窄屏碎片较小，仍优先 PC。
- 单文件通过本地 HTTP 单独载入，没有额外网络资源请求，源码与资源已内嵌。当前浏览器自动化入口限制直接导航 file://，因此本轮不声称已经重新完成双击路径的浏览器测试。
- 主视图统计约 98 次绘制、17296 个三角形，统计不覆盖阴影的全部额外工作。印边从独立叠层合并到卡面金属遮罩，减少约十二次绘制。
- 当前测试环境冷启动早期短时采样约 35–39 FPS；资源和着色器预热后，1440×1000 主视图连续四次短时采样均为 60 FPS。不能据此承诺其他显卡、低配电脑或长时间运行表现。尚未做正式硬件矩阵、显存与功耗分析。

## 这次试玩要决定的事

优先判断：是否接受这套卡面风格；卡图的细节是否值得为每张新增内容投入；桌面是否衬托而非压过卡片；连续归位和入册是否舒服。如果方向成立，再固定字体、降低干扰纹理、完成正式引擎选择和一张卡的人工流程计时。正式产品引擎仍未确定，浏览器样板不代表已经选定 Three.js 作为发行技术。
