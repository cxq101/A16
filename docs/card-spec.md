# 卡牌现行规范

本文件是卡牌信息的唯一现行设计依据。后续用户要求覆盖早期讨论；现有原型及旧图仍可能保留已删除信息，不能反向覆盖本规范。

## 正面与背面

采用用户选择的 **B：全幅插画式卡面**。名称、品质、类别、简短背景文案与编号直接出现在卡牌上，边框与信息底衬保证辨认。

| 信息 | 现行要求 |
| --- | --- |
| 名称与形象 | 每张收藏卡具有独立名称与形象 |
| 稀有度 | 每卡恰好一个；名称、等级和表现体系可调整扩展 |
| 类别 | 可同时多个，例如「人物＋灵兽」；类别体系可调整扩展 |
| 背景文案 | 保留，当前样例为一至两句；不承载战斗效果 |
| 编号 | 正面仅显示号码，例如 `001`；不显示 `/总数` 或 `???` |
| 系列归属 | 每卡恰好一个系列；**正面不显示系列徽记或系列名称** |
| 系列卡背 | 不同系列使用不同卡背；原正面系列徽记移至背面 |
| 属性 | **删除，不保留现行属性字段**；早期「水＋月」与多属性提案已废止 |
| 战斗信息 | 不加入费用、攻击、防御、生命或战斗技能等字段 |
| 工艺文字 | 不显示「烫金」「闪卡」等工艺文字或专用标识；通过材质表现 |

卡背已明确迁移的是系列徽记，未要求把系列名称文字也迁移到背面。当前无字徽记背面效果图可作为待审阅方案。

编号显示为纯号码，不代表后台可以缺少稳定标识。建议未来使用稳定 `cardId`，但具体字段方案与编号按系列或全局分配仍待技术设计确认。

## 关联形态与品质

用户不希望同名同形象只因工艺不同而成为多张收藏卡。例如同一基础角色的邪恶变化，应通过新名称、新形象及堕落设计形成另一张卡。关联通过设计体现，卡面不直接打印「原型／进化／同角色」标签。

内部是否存储关联族谱只是未来数据提案，不属于当前已批准字段。类别和稀有度应采用可扩展配置，避免在渲染代码中写死完整体系。

初始品质研究使用**普通、稀有、传说**。用户已要求宽一些的边框和更明显的品质表现。品质符号＋品质名继续作为识别信息，同时增加边框、装饰、颜色层次和局部材质差异。工艺不是额外的收藏身份，不增加同名换皮卡。
