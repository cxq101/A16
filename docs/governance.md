# 项目治理规范

## 接入范围与版本

本项目于 2026-11-24 采用个人 `project-formalization` 技能对应的规范 **1.0.0**，接入记录为 [.project/formalization.json](../.project/formalization.json)。本文件保存项目内适用约束，新环境无需依赖原机器的技能绝对路径即可理解项目规则。

当前 `formalized` 仅指文档、目录职责、版本来源和交接规则已接入；不表示生产引擎、素材、测试或商业计划已就绪。技能更新不自动升级项目，升级需评估差异并显式修改接入记录。

## 权威与历史

README 只作为入口，不复制完整设计。玩法、卡牌、美术、交互、技术各有独立权威文档，映射见接入记录。决策记录保留覆盖关系，具体规则修改同步到对应权威文档。

优先级：用户最新明确要求 → 对应现行设计文档 → 当前实现状态 → 历史说明／生成图。若文档遗漏或冲突，记录并修正，不以旧图文字补回已删除字段。提案需显式标注；待审阅素材不得登记为已批准。

`fragment-demo/README.md`、`3D-STUDY.md`、`ART-DIRECTION.md` 为原型说明与历史研究，不作生产设计规范。资产子目录清单是生成批次记录，项目级选择状态只在 `.project/artifacts.json` 管理。

## 目录职责

| 目录 | 所有者与职责 |
| --- | --- |
| `.project` | 项目治理与状态登记，不放秘密凭据 |
| `docs` | 当前设计、决策、参考与交接；验证记录进入 `docs/validation` |
| `fragment-demo` | 既有可运行原型，维持布局，不在正式化时顺手迁移 |
| `fragment-demo/dist` | 原型源码与部分生成物混合；逐文件判定，禁止整体清理 |
| `fragment-demo/art-proposals` | 视觉研究、提示词与批次清单；不等于生产资产目录 |
| `outputs`、`work` | 原有预留／临时工作区，无权威规则职责 |

生成物关系见技术基线。修改生成卡面需改 `art-assets.cjs` 等母源并重建；原型中的手写 `dist` 文件则直接按源码维护。依赖、缓存和临时测试产物不纳入权威内容。

## 公共核心与业务边界

目前没有生产核心库。生产选型时优先评估 BaX 是否适配所选引擎与项目维护成本，并记录采用或不采用的依据，不为形式完整而引入框架。

可复用的输入封装、存档基础设施、资源加载等公共机制可进入核心层；卡牌归属、类别、品质、收卡槽映射、拼接规则、成长解锁与经济由业务层拥有。只有出现真实复用需求才抽取，不把单项目内容硬编码进通用库，也不由核心库反向依赖业务。

## 独立版本对象

- 治理规范版本：`.project/formalization.json` 的 `standardVersion`。
- 接入记录结构：同文件 `schemaVersion`，不等于治理版本。
- 依赖版本：`fragment-demo/package.json` 与锁文件；不等于产品版本。
- 美术登记结构：`.project/artifacts.json` 的 `schemaVersion`；目录 v1/v2 是历史效果稿批次。
- 产品发布、生产资源包、正式存档版本：尚未建立，不编造统一 `1.0.0`。原型存档键及迁移见技术基线。
