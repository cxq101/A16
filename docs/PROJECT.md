## 1. 项目定位与范围

### 当前结论

**一款以不同状态的卡牌及其碎片为整理对象，让玩家通过辨认、拼接、去污与归位，将混乱逐步恢复为秩序的休闲整理游戏。** 当前卡面以奇幻内容为样例。

游戏发生在一间 TCG 卡牌收藏室：某种事件使卡牌散落各处，部分出现破碎与污渍。玩家使用唯一一个容量受限、后续可升级的容器收集它们，带回工作台整批倒出，按状态处理，再通过台旁的收卡设备归档。随着整理数量增加获得加速能力，最终完成所有卡牌的整理。完整卡与每片碎片均占 1 格；验证版初始容量为 12 格，归档 2 张扩容至 18 格、4 张提升清理效率、6 张解锁小范围批量拾取；事件内容、效率倍率、拾取范围及正式版数值尚未确定；完整流程以 [玩法设计](#gameplay) 为准。

核心驱动力是玩家亲手把混乱变得有序：混杂对象逐渐变得清晰，破碎图像恢复完整，污渍被清除，散落卡牌最终归位。并非每张卡都要拼接：有的原本完整，有的需要去污，有的以碎片形式出现。拼接和去污都是按对象状态采用的整理手段；污渍与破碎可以叠加，由于污渍遮挡卡牌内容，需要先清理、再拼接。收藏进度记录整理成果，漂亮卡面增强完成反馈。不能将「收藏是长期动力」作为项目的默认设计前提。

即使没有新卡或稀有卡奖励，一桌从混乱到整齐的过程也应有独立满足感。整理操作、过程变化和完成状态共同构成核心体验。

用户已体验原型，反馈有继续游玩的动力；也确认三维视角提升体验、倾斜没有影响辨认归位。玩法方向可以继续推进，当前主要风险转向美术品质、制作成本及收藏操作的顺畅度。这是原型反馈，不等于市场销量验证。

1. 使用 Godot 样板评估效果与操作，确认最终美术方向和目标硬件；当前引擎版本已锁定。
2. 以少量卡牌验证最终画风、分层资产、三维材质、六片辨认及实际工时。
3. 以少量对象串联收藏室收集、受限容器、工作台处理与对应目录归档，验证翻页收卡和连续整理反馈，避免在大量内容前扩建系统。
4. 验证整理数量带来的效率提升和全部整理目标，再确定纵向切片内容、正式版规模与排期；经济系统不是默认必需项。

### 成功判断

核心循环需同时满足：玩家能清楚感知混乱正在减少、秩序正在建立；碎片易辨认但仍有寻找乐趣；操作顺畅且结果可信；图像补齐与卡片归位都有明确反馈；没有新卡奖励时，完成一桌仍有满足感；增加内容和品质不会让制作成本失控。具体试玩人数、数值阈值和商业目标待定义。

当前已授权指定 GitHub 仓库的初始提交与推送；游戏部署、商店发行及创建新对话需对应授权。

## 2. 游戏流程与成长

### 体验目标与故事前提（已确认）

核心驱动力是把混乱整理成秩序。收藏室因某种事件变得散乱，卡牌出现完整、破碎、有污渍及复合状态；事件内容待设计。卡牌是整理对象，拼接与去污是按状态采用的手段，归档记录整理成果。没有额外新卡奖励时，完成一桌整理也应令人满足。

秩序恢复同时体现在房间散落物减少、工作台上的污渍消除和图像复原、收卡设备空位填满。Godot 三卡样板已完成用户试玩验证，可以替代旧演示；完整十二卡与全部成长仍待扩展和验证。

### 完整流程（已确认）

第一人称在收藏室寻找 → 将卡牌及碎片收入唯一容器 → 主动返回工作台，切至固定倾斜视角 → 整批倒出 → 按状态翻正、去污、拼接 → 在台旁收卡设备手动或快捷归档 → 按归档数量自动获得能力 → 继续整理，最终全部卡牌正确归档。

容器未满也可返回；桌面未清空也可继续外出收集并倒入。多批可暂存，过多会掉落；落地物可重新收集，不消失、不额外损坏。不强制清空一批才开始下一批。

| 对象状态 | 处理路径 |
| --- | --- |
| 完整、干净 | 按需翻正 → 归档 |
| 完整、有污渍 | 按需翻正 → 单对象清理 → 手动拿去归档 |
| 破碎、干净 | 翻正碎片 → 固定拼接区 → 拼成整卡后手动拿去归档 |
| 破碎、有污渍 | 翻正 → 对带污碎片先清理 → 拼接 → 整卡归档；干净碎片可直接拼接 |

同一卡允许部分碎片干净、部分带污，不要求先清完整桌或整卡全部碎片。边找边拼，自由切换目标；同卡碎片可跨位置、跨批次收集，部分拼接进度持续保留。每张卡只有一份，完整卡或唯一一套碎片对应唯一归档位置。

### 归档计数、成长与终局

只有**完整、干净且正面朝上的卡牌进入正确归档位置**，才计为完成 1 张。每张卡最多计数一次，手动与快捷归档遵守同一计数规则。清理、拼接、重新搬运、拾取掉落物及欣赏已归档卡均不重复计数。

达到归档数量节点后自动获得三项能力，不购买、不手动领取：容器扩容、清理效率提升、小范围批量拾取。清理提升仍保留手动擦拭；批量拾取每对象仍占 1 格，受剩余容量限制。

全部卡牌正确归档后展示完成结果，允许留在收藏室自由查看卡牌与收卡设备。不限时整理，可随时暂停；暂停时所有物品停止运动，恢复后继续。

- 每次操作应清楚减少混乱、恢复内容或填补归档空位，辅助与升级保留亲手整理的参与感。

- 检查暂停、读档、快捷归位途中恢复的状态一致性及一次归档只计数一次。

## 3. 卡牌信息规范

本节是卡牌信息的唯一现行设计依据。后续用户要求覆盖早期讨论；现有原型及旧图仍可能保留已删除信息，不能反向覆盖本规范。

### 正面与背面

名称、品质、类别、简短背景文案与编号直接出现在卡牌上。全幅布局、边框与信息底衬等视觉要求见 [美术文档](ART.md#art)。

| 信息 | 现行要求 |
| --- | --- |
| 名称与形象 | 每张收藏卡具有独立名称与形象 |
| 稀有度 | 每卡恰好一个；名称、等级和表现体系可调整扩展 |
| 类别 | 可同时多个，例如「人物＋灵兽」；类别体系可调整扩展 |
| 背景文案 | 保留，当前样例为一至两句；不承载战斗效果 |
| 编号 | 正面仅显示号码，例如 `001`；不显示 `/总数` 或 `???` |
| 系列归属 | 每卡恰好一个系列；**正面不显示系列徽记或系列名称** |
| 系列卡背 | 不同系列使用不同卡背；原正面系列徽记移至背面 |
| 属性 | **删除，不保留现行属性字段**；早期「水＋月」与多属性提案已废止 |
| 战斗信息 | 不加入费用、攻击、防御、生命或战斗技能等字段 |
| 工艺文字 | 不显示「烫金」「闪卡」等工艺文字或专用标识；通过材质表现 |

卡背已明确迁移的是系列徽记，未要求把系列名称文字也迁移到背面。当前无字徽记背面效果图可作为待审阅方案。

编号显示为纯号码，不代表后台可以缺少稳定标识。建议未来使用稳定 `cardId`，但具体字段方案与编号按系列或全局分配仍待技术设计确认。

### 关联形态与品质

用户不希望同名同形象只因工艺不同而成为多张收藏卡。例如同一基础角色的邪恶变化，应通过新名称、新形象及堕落设计形成另一张卡。关联通过设计体现，卡面不直接打印「原型／进化／同角色」标签。

内部是否存储关联族谱只是未来数据提案，不属于当前已批准字段。类别和稀有度应采用可扩展配置，避免在渲染代码中写死完整体系。

初始品质研究使用**普通、稀有、传说**。品质的边框、颜色、装饰与材质方案见 [美术文档](ART.md#art)；这里维护品质身份与可扩展规则，不重复维护视觉方案。

## 5. 操作与交互

### 当前运行方向

第一人称收藏室与固定倾斜工作台由 Godot 实现，并已完成用户效果验证。继续维护当前 Godot 工程，具体镜头参数与美术表现按后续试玩调整。

### 已确认的整理操作

以下是已确认设计；具体 Godot 实现范围见技术章节，不能把设计要求等同于全部功能已经完成。

#### 房间探索、工作台视角与翻面

- 收藏室采用第一人称自由移动，走动寻找和收集。
- 靠近工作台主动交互，切换到固定倾斜桌面视角；退出后恢复第一人称。
- 携带容器，以准星对准对象，按一次拾取键直接收入容器，并显示容量变化。
- 完整卡与碎片正反面随机；准星或鼠标指向对象后按翻面键原地翻面，房间和桌面均可用。翻转指背面到正面，不把平面旋转写成既定操作。

#### 容器、倾倒与桌面掉落

- 一个容器，完整卡和每片碎片各占 1 格，污渍不额外占容量；验证版初始 12 格、归档 2 张升至 18 格。
- 满载无法继续拾取，需要返回腾出容量；未满可随时返回。
- 解锁后小范围批量拾取附近多个对象，仍受剩余容量限制。
- 整批倒到桌面，再自由整理。桌面未清空可继续收集、再次倒入。
- 倒入过多会掉落；落地物可用同一容器重新收集，不消失、不额外损坏。堆积与掉落的具体物理参数待验证。

#### 单对象清理区

- 需要去污的完整卡或碎片放入专门清理区，一次一个对象。
- 按住鼠标来回擦拭，污渍逐渐消失、显露内容；大部分清除后自动去少量残留并完成，阈值待试玩。
- 完成后玩家手动拿走，碎片送拼接、完整卡送归档，腾空后才处理下一对象。
- 同一卡的干净碎片翻正后即可拼接，带污碎片先清理，不强制整卡全部碎片清完才开始。

#### 固定拼接区

- 全部目标开局可选，玩家自由选择当前卡，默认显示淡化原图。
- 2×3 共 6 片，矩形网格凹凸咬合；同一卡碎片可不同位置、不同批次收回。
- 只接受正面朝上且干净的碎片；正确位置附近吸附，错误放置返回拿起前位置并轻微提示，不扣分、不损坏。
- 正确吸附后固定为已完成部分；切换目标保留各卡的部分进度。
- 整卡完成后合成一张完整卡，留在拼接区，由玩家手动拿走归档。

#### 台旁收卡设备

- 参考《再拆亿包》的实体翻页收卡设备，放在工作台旁，归档无需离开工作台。
- 只接受完整、干净、正面朝上的卡；放入唯一正确位置后才计数。
- 手动翻页拖放与快捷归位并存。快捷归位开局可用，玩家主动触发一次，只处理当前拿起的一张卡，自动翻到目标页并放入正确位置。
- 条件不符或错位时返回拿起前位置，简短提示原因，不扣分、不损坏。
- 正确归档后填满空位、即时更新数量、给简短声光反馈，可立即继续；放大欣赏由玩家主动打开。
- 按系列分目录未获确认，目录组织、格数、具体按键及动画时长仍待细化。本项目规则不等于已核实的参考游戏原版全部输入。

#### 剩余对象提示

- 覆盖房间、容器和工作台中的所有未归档卡牌或碎片，已归档卡不再提示。
- 可随时主动触发，不消耗次数或货币，每次短暂指出一个未归档对象的位置，再由玩家处理。
- 具体显示方式和时长待定，需覆盖未完成拼接中的剩余目标，避免仅检索房间地面。

#### 存档、暂停与完成后查看

- 单一自动存档；保存本局卡牌及随机状态、房间和桌面位置、正反面、容器内容、部分清理与各卡拼接进度、归档、成长及完成状态。
- 继续游戏恢复退出前状态，不重新随机；重新开始前提示将覆盖当前进度并确认。
- 不限时，可随时暂停；所有物品停止运动，恢复后继续。
- 全部归档后展示结果，允许留在收藏室自由查看；新手引导暂不加入，后期看试玩情况。
